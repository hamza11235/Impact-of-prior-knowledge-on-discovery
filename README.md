# Prior Knowledge versus New Evidence

A controlled diagnostic for studying how language models combine previously supplied
scientific knowledge with new numerical observations.

[![Notebook 1: in-context baseline](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/hamza11235/Impact-of-prior-knowledge-on-discovery/blob/main/notebooks/prior_evidence_demo.ipynb)
[![Notebook 2: weight prior](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/hamza11235/Impact-of-prior-knowledge-on-discovery/blob/main/notebooks/02_weight_prior_and_sequential_revision.ipynb)

This repository is being assembled experiment by experiment. The first completed block
asks whether a fictional scientific law supplied in context biases Qwen3-8B against
recovering a conflicting law from clean, controlled measurements.

## Experiment 1: in-context prior versus evidence

The fictional prior is

\[
L_A:\qquad \tau = 3\frac{mr^2}{q},
\]

while the observations are generated by

\[
L_B:\qquad \tau = 3\frac{mr}{q^2}.
\]

The evidence uses controlled one-variable-at-a-time sweeps, allowing each exponent to be
inferred from numerical ratios without an external calculator.

Before testing prior conflict, a replicated feasibility gate established that the base
model could solve this task. Across 20 independently generated datasets and five samples
per dataset, 96 of 100 generations returned the exact target law in the requested schema.
The other four traces also derived the correct law but either violated the output contract
or reached the token limit before returning final JSON.

The matched conflict comparison used ten new datasets:

| Arm | Evidence | Exact valid \(L_B\) outputs | Scientifically correct traces | Returned \(L_A\) |
|---|---|---:|---:|---:|
| No prior | \(L_B\) | 9/10 | 10/10 | 0/10 |
| \(L_A\) stated in context | \(L_B\) | 10/10 | 10/10 | 0/10 |
| Bare \(L_A\) statement | \(L_B\) | 9/10 completed | 10/10 | 0/10 |

The bare arm removes the sentence explicitly warning that observations may contradict the
background law. Its one missing final answer was a truncation after the trace had already
derived exact \(L_B\).

**Result:** under clean and decisive controlled evidence, an \(L_A\) prior stated in
context produced no detectable bias toward \(L_A\).

See [the experiment record](experiments/01_in_context_vs_base/README.md) for the protocol,
prompt variants, result definitions, and limitations.

## Experiment 2: a weight-encoded prior

The second block introduces \(L_A\) through an 80-step LoRA adapter and then reveals
conflicting \(L_B\) evidence sequentially. The selected adapter retrieves \(L_A\) before
evidence in all three runs, while the untouched base model reports no prior. Both arms
ultimately recover \(L_B\); the adapter takes one additional evidence batch in one of
three paired runs.

The adapter is explicitly treated as a partial, prompt-dependent prior rather than
fully portable knowledge: it passes 3/6 held-out recall forms with thinking enabled and
0/6 without thinking.

See [the weight-prior experiment record](experiments/02_weight_prior/README.md) for the
training data, final adapter, evaluation gates, raw sequential traces, and reproduction
commands.

## Interactive notebooks

Both notebooks can be opened directly in Colab using the badges above. In their default
cached mode, the first cell fetches this repository and all checked-in artifacts; no model
download, GPU, or credentials are required.

Open [Notebook 1: the in-context baseline](notebooks/prior_evidence_demo.ipynb) for the
first experiment. Its default cached mode:

- requires no model download;
- lets the reviewer choose a dataset seed, target law, and prior arm;
- verifies the checked-in artifact checksums;
- regenerates the controlled evidence table;
- displays the exact three prompt variants;
- selects and directly scores an individual cached response;
- loads all 130 raw generation records;
- recomputes the feasibility and in-context result tables from those raw records.

The same notebook can generate one fresh Qwen response on Apple silicon, or score a
response pasted from another model or service.

Open
[Notebook 2: the weight prior and sequential revision](notebooks/02_weight_prior_and_sequential_revision.ipynb)
for the selected LoRA experiment. It:

- verifies the checked-in adapter, curriculum, results, and raw-run checksums;
- exposes the exact training configuration and representative curriculum examples;
- reports the portable-recall and reasoning-retention gates;
- recomputes all three paired sequential trajectories from raw artifacts;
- lets the reviewer choose the seed, model arm, and evidence stage;
- optionally reproduces one complete live sequential run on Apple silicon.

## Install

The deterministic data, prompt, parsing, and scoring tests do not require model weights:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python -m unittest discover -s tests -v
```

To run the notebook:

```bash
python -m pip install -e ".[notebook]"
jupyter lab notebooks/prior_evidence_demo.ipynb
```

To run Qwen3-8B locally on Apple silicon:

```bash
python -m pip install -e ".[mac,notebook]"
```

Model weights are fetched and cached automatically by `mlx-lm`; they are not stored in
this repository.

## Reproduce a dry-run prompt

```bash
prior-evidence-gate \
  --condition conflicting \
  --prior-arm in_context_bare \
  --start-seed 2000 \
  --dry-run \
  --output-dir outputs/prompt-preview
```

## Run one model comparison

```bash
prior-evidence-gate \
  --condition conflicting \
  --prior-arm in_context_bare \
  --datasets 1 \
  --samples-per-dataset 1 \
  --start-seed 2000 \
  --max-tokens 6144 \
  --output-dir outputs/in-context-smoke
```

## Current scope

The repository currently contains the base feasibility and in-context-prior comparison,
plus the selected LoRA weight-prior and sequential-revision experiment. Noise sweeps and
the abandoned adapter-development variants are outside the reported scope.
