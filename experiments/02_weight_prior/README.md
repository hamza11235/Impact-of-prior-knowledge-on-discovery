# Experiment 2: a weight-encoded prior and sequential revision

## Question

Can a small LoRA adapter teach Qwen3-8B a fictional scientific law as persistent
knowledge while preserving its ability to infer a conflicting law from new evidence?

The taught law is

$$
L_A:\qquad \tau = 3\frac{mr^2}{q},
$$

and the conflicting evidence is generated by

$$
L_B:\qquad \tau = 3\frac{mr}{q^2}.
$$

This experiment follows the in-context baseline in
[`../01_in_context_vs_base`](../01_in_context_vs_base/README.md). Unlike that first
experiment, the prompt does not supply $L_A$: the selected arm must retrieve it from
the LoRA parameters.

## Selected adapter

Only the final selected pilot is included here:

- base model: `mlx-community/Qwen3-8B-4bit`;
- method: completion-only LoRA SFT;
- trainable layers: 16;
- rank: 8;
- scale: 16;
- learning rate: $2\times10^{-5}$;
- effective batch size: 4;
- sequence length: 2,048;
- iterations: 80;
- random seed: 271828;
- peak measured training memory: 8.051 GB.

The materialized curriculum contains 28 training, 7 validation, and 7 test examples.
The training split contains 24 target-law examples and four disjoint-domain
law-induction retention examples. Target examples span equation recall, structured
parameters, prose dependencies, forward applications, inverse applications, and
qualitative consequences.

The final 37 MB adapter is checked in at
[`adapter/adapters.safetensors`](adapter/adapters.safetensors). Intermediate checkpoints
and abandoned adapter variants are intentionally excluded.

## Knowledge-acquisition and retention gates

The adapter produced a real but incomplete prior:

| Gate | Result |
|---|---:|
| Training-shaped $L_A$ recall | pass |
| Portable recall, thinking enabled | 3/6 |
| Portable recall, thinking disabled | 0/6 |
| Confirming $L_A$ evidence | exact pass |
| Decisive conflicting $L_B$ evidence | exact pass |
| Held-out fictional-domain law induction | exact pass at 6,144 tokens |
| Simple algebra | pass |

Consequently, the adapter is not presented as robustly internalized scientific
knowledge. It is a prompt- and mode-dependent weight prior that is strong enough to
preregister $L_A$ before any new evidence in the main sequential protocol.

## Sequential evidence protocol

The model first records its current neryx law before seeing any observations. Evidence
from $L_B$ is then revealed cumulatively:

1. baseline and two $m$ interventions, which are compatible with both laws;
2. one anomalous $r$ intervention;
3. a replicated $r$ intervention and the first $q$ intervention;
4. the remaining $q$ and $s$ interventions.

Neither candidate law is named in the prompts, and the system is not instructed to
override its prior. The primary outcome is the first stage at which the model selects
$L_B$.

| Seed | Base prior | Weight prior | Base first $L_B$ | Weight first $L_B$ |
|---:|---|---|---:|---:|
| 7100 | none | $L_A$ | 3 | 3 |
| 7200 | none | $L_A$ | 3 | 3 |
| 7300 | none | $L_A$ | 3 | 4 |

Both arms ultimately recovered $L_B$ in all three paired runs. The weight-encoded
prior delayed the final law selection by one evidence batch in one run—the run whose
first $q$ intervention produced the weakest conflict with the $q^{-1}$ prior.

The supported result is therefore:

> The selected LoRA produced a retrievable but incomplete $L_A$ prior. That prior
> remained defeasible: it did not block discovery of $L_B$, although it delayed
> selection once under the least decisive early contradiction.

Three paired runs do not establish a general statistical scaling law for prior
resistance.

- `artifacts/`: original training log, historical training configuration, and all six
  raw sequential runs;
- `SHA256SUMS`: integrity manifest for the complete experiment block.

## Reproduce the adapter

On Apple silicon:

```bash
python -m pip install -e ".[mac]"
mlx_lm.lora \
  --config experiments/02_weight_prior/training/reproduce.yaml
```

The reproduced adapter is written under `outputs/`, leaving the checked-in reference
adapter unchanged.

## Evaluate portable recall

```bash
prior-evidence-portable-recall \
  --adapter-path experiments/02_weight_prior/adapter \
  --thinking \
  --max-tokens 4096 \
  --output outputs/portable-recall-thinking.json
```

## Run one sequential update

```bash
prior-evidence-sequential-update \
  --arm weights \
  --adapter-path experiments/02_weight_prior/adapter \
  --dataset-seed 7100 \
  --prior-generation-seed 10007100 \
  --stage-generation-seeds 20007101,20007102,20007103,20007104 \
  --stage-max-tokens 6144 \
  --output outputs/sequential-update-seed7100-weights.json
```

The equivalent base command uses `--arm base` and omits `--adapter-path`.
